# Embedded Data — PROGMEM Implementation

## Vue d'ensemble

Les fichiers de données structurelles (types, catalogues) sont **embarqués dans le firmware** au lieu d'être stockés sur LittleFS.

Cette approche **professionnelle** permet de distribuer la bibliothèque via PlatformIO sans dépendance au système de fichiers.

---

## Architecture

### **Avant (LittleFS) :**
```
ESP32 Flash
├── Firmware : 1.4 MB
└── LittleFS : 1.2 MB
    ├── board_types.json    (100 KB)
    ├── device_types.json   (10 KB)
    ├── bus_types.json      (5 KB)
    ├── i2c_known.json      (2 KB)
    └── config.json         (5-20 KB)
```

**Problèmes :**
- ❌ Fichiers doivent être uploadés manuellement
- ❌ Peuvent être corrompus (LittleFS)
- ❌ Impossible à distribuer via PlatformIO lib
- ❌ Gaspille 117 KB de LittleFS

### **Après (PROGMEM) :**
```
ESP32 Flash
├── Firmware : 1.41 MB (+3.4 KB gzippés)
└── LittleFS : 192 KB (optimisé)
    └── config.json         (5-20 KB)
```

**Avantages :**
- ✅ Types toujours sync avec le firmware
- ✅ Impossible de corrompre (ROM)
- ✅ Distribuable via PlatformIO
- ✅ Économise 1+ MB de LittleFS
- ✅ Compression gzip → seulement 3.4 KB
- ✅ Cache navigateur (24h)

---

## Compression

Les fichiers JSON sont **minifiés** puis **gzippés** (niveau 9) :

| Fichier | Original | Gzippé | Ratio |
|---------|----------|--------|-------|
| **board_types.json** | 15 385 bytes | 2 231 bytes | **14%** |
| **device_types.json** | 2 716 bytes | 632 bytes | **23%** |
| **bus_types.json** | 957 bytes | 329 bytes | **34%** |
| **i2c_known.json** | 650 bytes | 241 bytes | **37%** |
| **TOTAL** | **19 708 bytes** | **3 433 bytes** | **17%** |

**Gain firmware :** seulement 3.4 KB pour tous les catalogues !

## Build automatique

Les headers PROGMEM sont **régénérés automatiquement** à chaque compilation :

```
Source JSON                             Header PROGMEM
──────────────────────────────────────  ─────────────────────────────────────
lib/MrJ-RailwayFX.local/data/          lib/MrJ-RailwayFX.local/src/api/
  ├── board_types.json      ──────────→   ├── embedded_board_types.h
  ├── device_types.json     ──────────→   ├── embedded_device_types.h
  ├── bus_types.json        ──────────→   ├── embedded_bus_types.h
  └── i2c_known.json        ──────────→   └── embedded_i2c_known.h

Script: scripts/build_embedded_data.py
Hook:   platformio.ini → extra_scripts = pre:scripts/build_embedded_data.py
```

**Workflow :**
1. Modifier `lib/data/device_types.json`
2. Compiler : `pio run`
3. Script auto-régénère `embedded_device_types.h`
4. Firmware contient la nouvelle version ✅

## Serving via API

Les données sont servies **directement depuis PROGMEM** avec compression gzip :

```cpp
// Avant (LittleFS)
void _onGetBoardTypes() {
  File f = LittleFS.open("/board_types.json", "r");
  server.streamFile(f, "application/json");
  f.close();
}

// Après (PROGMEM)
void _onGetBoardTypes() {
  server.sendHeader("Content-Encoding", "gzip");
  server.sendHeader("Cache-Control", "max-age=86400"); // 24h
  server.send_P(200, "application/json",
    (const char *)BOARD_TYPES_GZ, BOARD_TYPES_GZ_LEN);
}
```

**Avantages :**
- ✅ Pas d'I/O LittleFS (plus rapide)
- ✅ Données déjà compressées (économie bande passante)
- ✅ Cache navigateur 24h (réduit requêtes)
- ✅ Pas de risque de fichier manquant

## Endpoints API

| Endpoint | Source | Taille gzippée |
|----------|--------|----------------|
| `GET /api/board-types` | `BOARD_TYPES_GZ` | 2.2 KB |
| `GET /api/device-types` | `DEVICE_TYPES_GZ` | 632 bytes |
| `GET /api/bus-types` | `BUS_TYPES_GZ` | 329 bytes |
| `GET /api/i2c-known` | `I2C_KNOWN_GZ` | 241 bytes |

Headers HTTP :
```
Content-Type: application/json
Content-Encoding: gzip
Cache-Control: max-age=86400
```

Le navigateur décompresse automatiquement le gzip → transparent pour le client.

## Modification des types

### **Workflow développeur :**

```bash
# 1. Éditer le JSON source
code lib/MrJ-RailwayFX.local/data/device_types.json

# 2. Régénérer manuellement (optionnel, auto à la compile)
python3 scripts/build_embedded_data.py

# 3. Compiler et uploader
pio run -e zou_debug -t upload

# LittleFS upload N'EST PLUS NÉCESSAIRE pour les types !
```

### **Headers auto-générés :**

Les fichiers `embedded_*.h` sont **AUTO-GÉNÉRÉS** — ne jamais les éditer manuellement !

Chaque header contient :
```cpp
/**
 * @file embedded_board_types.h
 * @brief Embedded board_types catalog (gzipped JSON in PROGMEM).
 *
 * Auto-generated by scripts/build_embedded_data.py — DO NOT EDIT MANUALLY.
 * Source: lib/MrJ-RailwayFX.local/data/board_types.json
 *
 * Original size: 15385 bytes
 * Compressed:    2231 bytes (14% of original)
 *
 * Served by /api/board-types with Content-Encoding: gzip
 */

#pragma once
#include <Arduino.h>

const uint8_t BOARD_TYPES_GZ[] PROGMEM = {
  0x1f, 0x8b, 0x08, ...  // gzipped JSON
};

const size_t BOARD_TYPES_GZ_LEN = sizeof(BOARD_TYPES_GZ);
```

## Distribution via PlatformIO

Cette approche permet de **publier la bibliothèque** sur PlatformIO Library Registry :

```ini
# Dans le platformio.ini de l'utilisateur
[env:my_project]
lib_deps =
    MrJ-RailwayFX  # ← Types embarqués dans la lib !
```

**Aucun fichier à uploader** — tout est dans le firmware.

## LittleFS optimisé

Avec les types dans le firmware, LittleFS ne contient que **la config utilisateur** :

```
data/
└── config.json  (5-20 KB max)
```

**Partition table optimisée :**

```ini
; partitions_custom.csv
# Name,   Type, SubType, Offset,  Size,   Flags
nvs,      data, nvs,     0x9000,  0x5000,
otadata,  data, ota,     0xe000,  0x2000,
app0,     app,  ota_0,   0x10000, 0x1A0000,  # 1.6 MB
app1,     app,  ota_1,   0x1B0000,0x1A0000,  # 1.6 MB
spiffs,   data, spiffs,  0x350000,0x30000,   # 192 KB (optimisé)
```

**Gain :** ~1 MB de flash libre pour d'autres usages !

## Script de build

**Fichier :** `scripts/build_embedded_data.py`

**Fonctionnalités :**
- Lit JSON depuis `lib/data/`
- Minifie (supprime whitespace)
- Compresse gzip niveau 9
- Génère header C++ avec array PROGMEM
- Calcule stats (taille originale vs compressée)

**Exécution :**

```bash
# Manuelle
python3 scripts/build_embedded_data.py

# Automatique (hook PlatformIO)
pio run  # Exécute le script avant la compilation
```

## Migration depuis LittleFS

Si vous avez un projet existant utilisant LittleFS pour les types :

### **Étape 1 : Compiler avec les nouveaux headers**
```bash
pio run -e zou_debug
```

### **Étape 2 : Upload firmware**
```bash
pio run -e zou_debug -t upload
```

### **Étape 3 : Nettoyer LittleFS (optionnel)**
```bash
# Supprimer les anciens fichiers types de LittleFS
# Via WebUI : Config → Files → Delete
# Ou reflasher LittleFS avec seulement config.json
```

**Les types sont maintenant dans le firmware** — plus besoin de `uploadfs` pour eux !

## Dépannage

### **Headers pas régénérés**

Si les modifications JSON ne se reflètent pas :

```bash
# Forcer la régénération
python3 scripts/build_embedded_data.py

# Clean build
pio run -t clean
pio run
```

### **Erreur de compilation "BOARD_TYPES_GZ undeclared"**

Headers manquants → régénérer :
```bash
python3 scripts/build_embedded_data.py
```

### **API retourne ancien JSON**

Cache navigateur → forcer refresh :
```
Ctrl+F5 (ou Cmd+Shift+R sur Mac)
```

Ou attendre 24h (expiration cache)
